# 02: Web shell, coach API and Home food

**What to build:** The tracer bullet. The coach serves a small HTTP API, `fa-api` passes `/api/coach/` through, and the web UI becomes the coach page: bottom tabs Home · Week · Training · Setup (Week, Training, Setup placeholders), light/dark tokens following the phone's theme, day navigation (arrows + date picker) with values "as of that day", a refresh control that syncs and reloads, and one stale-data line only when stale. Home's food block works end to end: kcal eaten vs the coach's daily target with kcal left, protein / carbs / fat / fiber vs targets (eaten only before a phase), and its detail "week so far". The old day view moves to `/legacy`, reachable by URL only, never linked.

## Comments

- **Coach HTTP API:** `coach/src/fa_coach/web_adapter.py` (starlette + uvicorn, both already in `coach/uv.lock` through `mcp`; now direct deps, same versions) runs in the Telegram application's event loop (started in `post_init`), on `:8002` (`COACH_HTTP_PORT`), no `ports:` in compose. Routes: `GET /api/coach/<view>?…`, `POST /api/coach/refresh/<view>?…` (sync, then the view), `POST /api/coach/<command>` (JSON body). Errors are `{"error": "…"}` with 400/404/500. Reads run straight from stored data (synchronous, no lock); refresh and commands run under the Telegram adapter's lock and its outbox is sent (`TelegramAdapter.web_call`). uvicorn's signal capture is disabled so PTB keeps owning the process signals.
- **Pass-through:** `src/fitness_aggregator/coach_proxy.py`, `/api/coach/{path}` for GET/POST/PUT/PATCH/DELETE, method/path/query/body unchanged, response streamed back (`aiter_raw`), 502 `{"error": "The coach isn't reachable right now."}` when the coach is down. `FA_COACH_URL=http://coach:8002` in compose. Also added an SPA fallback in `api.py` (unknown non-`/api` paths serve `index.html`), needed for deep links such as `/home/food` and `/legacy`.
- **Seam and extension points (coach):** `Coach.view(name, query)`, `Coach.refresh(name, query)`, `Coach.command(name, body)` (`views.py`). Features register `@registry.view("week", schema="web_week")`, `@registry.view_part("home", "weight", schema="web_home_weight", order=20)` (Home blocks are parts of `home`, each in its own module and schema, so 03/04/05 don't touch `web_home.py`), and `@registry.web_command("setup/step-goal")`. Shared helpers: `views.day(query, now)`, `views.freshness(coach, now)`, `views.WebError(status, message)`. `views.errors(coach, name, data)` validates a view against its schema and every part against its own; tests call it. Schemas: `coach/coach-skills/schemas/web_*.schema.json` (+ examples, checked by `tools/validate.py`).
- **Read models:** `home` = {date, is_today, freshness} + part `food` (`features/web_home.py`): kcal eaten / `phases.daily_target` / left, macros vs the target's macros, fiber vs `nutrition.fiber_g_per_kg` × the macro reference weight (a range: `target_g` is its low end and the bar measures against it), `logged` complete/partial/missing (partial only for past days, via `daycheck`). `home/food` = the check-in week holding the day (starts on the check-in weekday, Monday without one), each day so far eaten vs target, plus totals over complete days. Freshness is "now" (stale per `data.sync_max_age_hours`), not as of the day shown.
- **Tests:** `coach/tests/test_web_home.py` (12 tests through the Coach seam: today, nothing logged, past day before/after an approved +100, before any phase, before the phase start, fresh vs stale, never synced, food detail with and without a phase, refresh syncs, bad/future day, unknown view). Full `docker compose run --rm test`: 293 passed. Deviation from strict red-first: the read-model tests were written as one batch before the implementation, then run.
- **Frontend extension points:** tokens and base classes `web/src/app/ui/tokens.css` (+ `.iconbtn`, `.page`, `.grid`, `.label`/`.big`/`.mid`, `.ok`/`.bad`/`.warn`); components in `web/src/app/ui/` (`app-card` with optional detail link, `app-meter`, `app-line-chart` (sparkline and larger chart with band, dots, gaps, empty state), `app-section-header`, `app-state` loading/error/empty, `app-icon`, `format.ts`, `tone.ts`); `web/src/app/shell/` (`app-tabs` bottom bar / desktop segments, `app-page-header` with `[prev]`/`[next]`/`[actions]` slots and `back`, `app-day-nav`, `injectDay()` for `?day=`, `app-refresh-button`, `app-stale-line`, `PlaceholderPage`); `web/src/app/api/` (`CoachApi.view/refresh/command`, `errorMessage`, `viewResource<T>(name)` with data/error/loading/refreshing signals, shared `Freshness` type). Routes: one file per tab (`pages/<tab>/<tab>.routes.ts`, lazily loaded); Week/Training/Setup are placeholders to replace there. Home blocks: add a component to `HOME_BLOCKS` in `pages/home/home-blocks.ts` (it gets the whole `HomeView` and `dayQuery`) and its key/type in `home.types.ts`; detail routes in `home.routes.ts`.
- **Design decisions:** the bar variant as in 01. Kcal over → number and bar in the destructive colour (as in 01); macro bars muted, protein/fiber turn green once reached, fat red when over. The food detail stays neutral per day (no red for small daily overages; the week's deviation is shown once, uncoloured). Past days show "Yesterday" / "N days ago" under the date. In detail views the back arrow replaces the day arrows (date picker stays). A failed refresh shows on the stale line ("Sync failed: …"). Geist is bundled from `@fontsource-variable/geist@5.3.0` (pinned, no external requests); `?theme=light|dark` forces a theme.
- **Legacy:** the old `App` moved unchanged to `web/src/app/legacy/legacy-day.ts` (selector and class renamed only), route `/legacy`, linked from nowhere. It now inherits the global page background and font.

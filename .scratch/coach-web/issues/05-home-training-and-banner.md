## Decisions (user, 2026-11-10, from ticket 01)

Overrides the text above where they differ: two blocks instead of one. **Gym** = lifting sessions (one line each: name, time of day, duration), with the lift trend line under them. **Other activities** = runs (distance, duration, **pace**), wrestling, extra sessions. No "planned" tag anywhere. Tapping either block opens the Training tab.

**Strength trend (user, 2026-11-10; decided by the orchestrator at the user's request):** a 4-week line showing whether lifting is improving overall. For each counting lift, each session's heaviest working set as estimated 1RM (effective load for bodyweight lifts, the same value the lift status uses); per ISO week, each lift's best value as % change from its first session in the 28-day window (after its latest baseline reset, if any); a lift needs ≥ 2 sessions in the window; excluded lifts never count. The plotted value per week is the mean % change over the lifts trained up to that week (each lift carries its last value forward). Shown as a thin line with one number ("+3.2 % in 4 weeks"): green when rising, neutral within ±1 %, red when falling. Computed in code in the coach read model, as of the shown day; core param `training.strength_trend_days: 28` and the ±1 % band reused from `training.e1rm_same_band_pct`. Shown small in the Gym block next to the trend line; tests cover rising, flat, falling, a reset lift, a lift with one session, and a past day.

**Strength trend on Home (user, 2026-11-10):** one single small graph, a visual, not a labelled chart: the line plus at most one or two numbers (e.g. "+3.2 %"), no axes, legends, per-lift lines or explanatory text.

## Comments

- **Read model (coach):** two `home` parts in their own modules. `training` (`features/web_home_training.py`, schema `web_home_training`): `gym` {sessions, trend, strength_trend} and `other` {sessions}; each session `{type, name, time, minutes, distance_km, pace_s_per_km, skipped}`. Gym = Hevy sessions, a planned lift reported done without a Hevy session, lifting extras. Other = Strava runs (HealthKit copies never), a planned run reported done when Strava has none, wrestling (planned from the active phase's start on, as counted activity counts it, or reported), planned "other" reported done, extras. Unreported runs/lifts/optional sessions aren't listed (they show once they sync); a planned session reported skipped stays listed with `skipped: true` (no "planned" state anywhere). `time` is HH:MM local from Hevy/Strava start (`history.days` exercises now carry `start_at`), else the plan's time or label, else null. Pace only for runs. `trend` = `progression.week` as of the day: counted lifts progressing / counted, stalls, PRs from the check-in week's start to the day (null before any lift). `banner` (`features/web_home_banner.py`, schema `web_home_banner`): null on past days and when nothing waits; else `{proposal: {id, type, change} | null, questions}` (latest open proposal of the active phase; questions = day questions asked and unanswered + open reset questions).
- **Strength trend (reusable for ticket 08):** `fa_coach/strength_trend.py`, `compute(coach, day)`; schema `web_strength_trend.schema.json` (referenced from `web_home_training`); web component `ui/strength-trend.ts` (`<app-strength-trend [trend] size="small|large">`, also exports the `StrengthTrend` type). Core param `training.strength_trend_days: 28` added (params.yaml, core_params schema, facts examples). Window = the 28 days ending on the day; weeks = the ISO weeks it touches (4 or 5 points). Paused lifts still count (only excluded ones are left out, as decided). Bodyweight lifts use the same `e1rm_kg` the status uses (not separately tested).
- **Tests:** `coach/tests/test_web_home_training.py` (17: lifting day, run day with pace, planned wrestling, skipped wrestling, extra session, only runs get a pace, no sessions incl. a pre-phase Friday, trend line today / past day, no trend before any lift, strength trend rising (with an excluded lift), flat, falling, reset lift, one-session lift, past day) and `test_web_home_banner.py` (6: none, open proposal, absent on past days, gone after approval, waiting question, answered question). Deviation from strict red-first: each test group was run red against the missing part, but the session listing and the strength trend were implemented ahead of most of their tests.
- **UI:** Gym card (label "Gym", links to /training): one line per session (name left; time · duration right), "No gym session yet today" when empty, then a divider and the trend line in plain words (zeros left out: "5 of 7 lifts progressing · 1 stall · 2 PRs this week") with the strength graph beside it (64 px thin line + "+3.2 %", green rising / gray flat / red falling, no axes or text). Other activities card (links to /training) only when the day has any; runs as "18:05 · 11.5 km · 62 min · 5:23 /km"; skipped struck through with "Skipped". Banner (`pages/home/home-banner.ts`) above the blocks, only on today: proposal → link to /week ("Proposal waiting: +100 kcal a day on average. Decide in Telegram."), questions → "The coach has a question for you in Telegram." (no link).

# 09: Training: lift detail

**What to build:** Tapping a lift opens its detail: a history chart of the heaviest working set as estimated 1RM with PRs and baseline resets marked (pull-ups and dips on bodyweight + added weight, same look), the last 3 sessions one line each (date, heaviest working set, status) with "show more", and controls to switch counts / not counted, pause or unpause, and mark a baseline reset with a reason. Controls use the same code paths and validation as the chat tools.

## Comments

- **Read model:** `lift` view (`coach/src/fa_coach/features/web_lift.py`, schema `web_lift.schema.json` + example), `GET lift?exercise_id=…&day=…&offset=0&limit=3` as of the day (404 for an exercise not in the synced Hevy history, 400 for a bad page). Head (status, latest set, not_judged_reason) from ticket 08's `web_training._lift`, plus `counts`, `paused`. `chart`: every session's heaviest working set as e1RM, oldest first, full history (not cut at the reset like the list's sparkline), each with `pr` and `baseline_reset`; bodyweight lifts on the effective load. Sessions without a working set in the rep range / at another location are left out of the chart but listed in `sessions` with their reason. `resets`: reason and the session that started each (null while pending). `sessions`: newest first, `{items, offset, total, next_offset}`; the page shows 3 and "Show more" fetches 10 at a time. `controls`: classification, paused reason, reset reasons.
- **Decisions:** session lines show how each session was judged then (progressing / same / declining / stall / new baseline / not judged + reason); `pr` is false while the lift is paused (as in the weekly facts). Classification and pause are current settings, not "as of the day" (no history of them is stored; same as ticket 08).
- **Commands:** counts / not counted and pause reuse ticket 12's `setup/exercises/classify {exercise_id, classification}` and `setup/exercises/pause {exercise_id, paused, reason?}` (coordinator's instruction, no duplicates); this ticket adds `lift/reset {exercise_id, reason, date?}` → `mark_baseline_reset` through `web_setup.run_tool` (the tool's schema, then the tool; refusals carry chat's words). The page sends no date, so the reset is from today (the next session, or today's if already trained), as in chat. No phase is required (chat doesn't require one either).

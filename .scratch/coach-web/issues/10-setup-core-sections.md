# 10: Setup: sections, phase and targets, messaging, activity values

**What to build:** The Setup tab lists its sections with one-line summaries (Phase & targets, Activity values, Messaging, Training plan, Exercises, Context notes, Profile, Measurements; later sections may show "coming soon" until 11–12 land). Phase & targets shows the active phase, phase week, base maintenance, surplus, step goal and current daily targets, and lets the user change the step goal. Messaging (check-in day and time, evening reminder time, daily message limit, step-floor window) saves directly. Activity values (run discount, wrestling kcal, lifting kcal) can be edited, and a change becomes a calibration proposal the user approves in Telegram. Starting a phase stays in Telegram.

## Comments

- **Coach, additive sections:** `features/web_setup.py` has the `setup` view (envelope `{phase_active, setup_open}`) and the helpers section modules use: `run_tool(coach, name, args, now)` (the chat tool's input schema, then the tool; a `ToolError` becomes a 400 with the tool's own reason), `require_editable` (409 without an active phase or while a phase setup is open), `editable`, `field`, `setup_range` (min/max from `phase_setup.schema.json`). Each section is its own module: a part `@registry.view_part("setup", "<key>", schema="web_setup_summary")` with a one-line summary, a view `setup/<section>` and its commands. Here: `web_setup_phase.py` (`phase_targets`, view `setup/phase-targets`, `POST setup/step-goal {step_goal}`), `web_setup_activity.py` (`activity`, `setup/activity`, `POST setup/activity {values}`), `web_setup_messaging.py` (`messaging`, `setup/messaging`, `POST setup/messaging {field, value}`). Tickets 11/12 add a module + schema + part (e.g. `training_plan`, `exercises`, `context_notes`, `profile`, `measurements`) and don't touch these files. Schemas `web_setup*.schema.json` + examples.
- **Shared code paths:** step goal and messaging run `record_setup_value` (keys `step_goal`, `logistics.<field>`); activity values run `propose_change` (`calibration_change`, source `user_request`, reason "Changed on the web page."), so the card with approve / reject / counter goes to Telegram through the outbox (commands run under the adapter lock, ticket 02). Only changed values are proposed; an identical open proposal comes back `referenced` (no second card); a blocked one (out of range, not a calibration key) is a 400 with the guardrail text (the blocked row is stored, as in chat).
- **Decisions:** web edits are refused (409) while a phase setup is open in Telegram, since `record_setup_value` would otherwise write into that setup instead of the active phase. Messaging saves one value per request; an empty value saves `null` (off). The Setup view is "now", not "as of a day". Phase & targets also shows today's target with macros, the average daily target, the MFP goal and rest / lifting / wrestling days at the step goal.
- **Change to chat code:** `record_setup_value` during a phase reported a bad value twice (the value's error, then the same error from the whole-setup schema check); the whole-setup check now runs only when the value itself is fine (`features/phase_start.py`). Chat gets the same single reason.
- **Reasons are chat's words**, e.g. "step_goal: 500 is less than the minimum of 1000", "run_kcal_discount = 1.5 is outside 0–1. …". The run discount is entered as a percentage on the page but the refusal names the share (open for ticket 13's polish if it reads badly).

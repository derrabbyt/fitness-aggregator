# 11: Setup: training plan

**What to build:** The Training plan section shows the saved week (sessions with times, optional runs) and lets the user change it for good or set this week's session status (skipped, done, extra with kcal or activity + duration), with the same rules and estimates as chat.

**Blocked by:** 10

**Status:** resolved

- [x] Read model and schema; commands shared with `update_training_plan` and `set_session_status`; tests cover a lasting change, a this-week skip, an extra session with estimated kcal, and a rejection
- [x] UI; build + screenshots in Comments; tests green

## Comments

- **Coach:** `features/web_setup_training_plan.py`: part `training_plan` (summary, e.g. "5 lifts · 1 wrestling · 2 runs · 5 optional", plus "· changes from <date>" when a lasting change starts later), view `setup/training-plan` (schema `web_setup_training_plan` + example): the saved week in force today (`days`, Monday first, sessions {id, time, name, type, optional}), `valid_from`, `upcoming`, `this_week` (each day's planned sessions with status / kcal / kcal_source, extras, `today`), `activities` (the MET table's keys for the estimate picker). Commands: `POST setup/training-plan/day {weekday, sessions, from?}` runs `update_training_plan` (lasting, from today unless `from`), returns the view; `POST setup/training-plan/session {date, status, session_id?, extra_id?, type?, name?, kcal?, activity?, duration_min?, distance_km?}` runs `set_session_status`, returns `{reported, section}` (`reported` is the tool's minus the model's `say`; null for skip / clear).
- **Change to chat code:** `training_plan.get_training_plan`'s body moved into a public sync `overview(coach, now)` (the tool returns it; the web view reads it), and `_week_dates` became `week_dates`. No behaviour change.
- **Decisions:** (1) The plan is editable with or without an active phase and while a phase setup is open, as in chat (it isn't a phase setup value); `editable` is false only without a saved plan. (2) The web reports this week only (chat also takes last week): another date is a 400 "Only this week's sessions can be reported here; report earlier ones in Telegram." (3) The web never sends the model's `kcal_estimate` (refused as an unknown field). session_kcal's refusals are worded for the model ("ask the user", "pass your own kcal_estimate"), so the web rewords those three (`_for_the_page`): "Code can't estimate the kcal: <code's reason>. Give the kcal.", "Give the kcal, or an activity and a duration so code estimates them.", "Give the duration (or the kcal)."; every other refusal is the tool's text. (4) Exercise lists aren't shown or edited here (Exercises is ticket 12's section); `distance_km` is accepted by the command but the page has no field for it. (5) The page shows Done and "+ Extra session" only for today and earlier days; Skip works ahead too.
- **Frontend:** `pages/setup/training-plan-page.ts` (route `/setup/training-plan`; Saved week: one `app-edit-row` per weekday with an inline session editor: time, name, type, optional, remove, + session, "From" date), `this-week-card.ts` (`app-this-week-card`: per day sessions with Skip / Done / Undo, extras with Remove, an inline editor for done / extra: type + name for extras, kcal, or activity + minutes for code's estimate; lifting / wrestling show only kcal since their setup value counts), types in `training-plan.types.ts` (not in `setup.types.ts`, to stay off ticket 12's lines). Confirmation lines: "Saved: 840 kcal, estimated from football, 90 min at 80.0 kg.", "Saved: 400 kcal (300 counted).", "Skipped for this week. The saved plan stays.". Phone: saved week first, then this week; desktop: two columns.
- **Tests:** `coach/tests/test_web_setup_training_plan.py` (21 through the Coach seam): the view and summary, a lasting change (from today, past week kept, summary), a change from a later day (upcoming), five refused changes (tool schema, time pattern, past week, bad weekday, missing field) with nothing saved, a this-week skip (saved plan unchanged, next week unaffected) and its undo, an extra session estimated by code (MET x trend weight x hours = 840) and its removal, the user's kcal on a done run, ten refused reports (no MET, no trend weight, no inputs, no duration, no type, last / next week, wrong session id, kcal out of range, kcal_estimate) storing nothing. Full `docker compose run --rm test` green; `ng build` green.
